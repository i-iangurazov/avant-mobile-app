# Лояльность — правила, расчёты, границы доказательств

Реализация — программа подтверждённых сантехников, не общий cashback всех покупателей. Роль customer сохраняется у pending/rejected/suspended. Администратор утверждает анкету; QR предъявляется кассиру; начисления приходят по чеку через защищённый pilot admin API. Заказ/резерв сам по себе бонус не начисляет. Награды обмениваются на баллы; списания бонусов при checkout нет.

**Коммерческие условия не утверждены.** README и POS контракт прямо называют значения пилотными. PASS ниже относится к реализации зафиксированных seed/test правил, не к коммерческой готовности. POS/1C, физическое сканирование QR и сверка двух мобильных устройств BLOCKED.

## Реестр правил

|Правило|Найденная реализация|Источник / расхождение / решение|
|---|---|---|
|Участник|Один account; отдельная анкета; доступ только approved|scripts/server/plumbers.ts:127,296; проверены pending/rejected/approved и повторная анкета. Native UI состояний не проверен.|
|Согласия|programConsent/dataProcessingConsent обязательны; сохраняются даты|app/plumber/apply.tsx:125; schema.sql:85. Текста правил/версии документа нет — D08.|
|Идентификатор|Случайный publicId и отдельный loyaltyCode; QR AVANT:PLUMBER:…|plumbers.ts:169; QR не содержит телефон/DB ID. Он не является bearer для admin/reward API.|
|Единица|Целые minor units:100 делится на100 при показе бонусов; деньги в тыйынах|loyalty.ts:64; programFormat.ts:1. Денежный эквивалент1 бонус=1 сом коммерчески не утверждён; не выводить его из format.|
|Базовая ставка|100bps=1%; фактическая ставка max(baseRate,levelRate)|schema.sql:145; loyalty.ts:291. При baseRate0 и уровне100bps начисление остаётся1%; нужен ответ Q01.|
|База|Суммы строк после внешних скидок; сумма строк равна totalMinor|loyalty.ts:190–233. Сервер не моделирует самостоятельно скидки POS, split payments и купоны — их семантика BLOCKED.|
|Исключения|Product ID/brand; исключённая строка даёт0|loyalty.ts:303; категорий в исключениях нет, не обещать категорийные правила.|
|Акции|Максимальный совпавший multiplier, не произведение акций; x2/x3 допустимы|loyalty.ts:307–318. Комбинация разных промо и граничные timestamps отдельно NOT TESTED.|
|Округление|BigInt деление с усечением вниз на уровне строки; promotional = total−base|loyalty.ts:315. Проверены0/1/99/100 minor; не все многострочные крайние случаи.|
|Событие начисления|Только ingested receipt; сохранён snapshot расчёта каждой строки|loyalty.ts:265; docs/pos-1c-contract.md. Production M2M отсутствует, pilot не заменяет POS.|
|Ожидание|14×24ч от purchaseAt, available_at; release с SKIP LOCKED|loyalty.ts:330,411. Тест сдвигал available_at в прошлое, не ожидал14 реальных дней. Timezone/DST и поздние события отдельно не закрыты.|
|Уровни|Rolling90д; Профи0, Эксперт100000 сом, Мастер300000 сом;1/1.25/1.5%|schema.sql:173–178. Пороги — пилот. Тест threshold смены уровня использовал собственные меньшие значения, затем вернул config.|
|Привилегии|Seed promises: приоритет, ранние заявки, бесплатная доставка по условиям, менеджер|Нет утверждённого процесса предоставления; ручные privileges требуют проверки владельцем, не PASS.|
|Возврат|Кумулятивно ограничены количество/сумма; пропорциональная сторнировка через integer deltas|loyalty.ts:478–592. Повтор/полный возврат проверены; возврат после расходования и отрицательный долг не согласованы.|
|Обмен|Reward cost целый >0; lock профиля+награды; available проверяется повторно|loyalty.ts:814. Частичное списание на товар, minimum order spend и checkout bonus cap — N/A текущей модели.|
|Отмена награды|Списание отменяется, bucket→none, availability восстанавливается один раз|loyalty.ts:868; проверено повторной отменой.|
|Истечение|Expiry нет; rolling window относится к уровню|N/A для текущего scope, не утверждение, что бизнесу expiry не понадобится.|
|История|API status/type/limit/offset; UI фильтры без пагинации|D11: default limit превращается в1, скрывает журнал.|
|Рефералы|Не найдены в актуальном API/навигации/описании текущего пилота|Не объявлены дефектом. Акции/обучение/заявки/отзывы входят в реализованный пилот.|
