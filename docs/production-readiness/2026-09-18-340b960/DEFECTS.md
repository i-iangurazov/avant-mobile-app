## Риски и вопросы, не подтверждённые end-to-end дефекты

- **R01 / P1 / до релиза проверить:** `src/lib/api/orders.ts:31,45` создаёт новый clientRequestId при каждом вызове. Потеря ответа после серверного COMMIT и повтор из UI могут создать второй заказ. Идентификатор нужно хранить на попытку оформления до согласованного результата. В этом аудите не имитировалась потеря ACK; одинаковый ключ не создал дубль.
- **R02 / P2 / CODE REVIEW:** `src/lib/bazaar/client.ts:342–374` получает одну страницу и сортирует только её; sort не передаётся серверу. Глобальный порядок цен нескольких страниц не гарантирован. Нужны staging товары с распределёнными по страницам ценами, сортировка на сервере и сквозной тест.
- **R03 / P1 / CODE REVIEW:** `scripts/server/auth.ts:60–85` выдаёт bearer на30 дней без server-side session/revoke; logout удаляет только локальную сессию. После выхода украденный токен может оставаться действующим. Нужен отзыв сессии, проверка после logout/password reset; сам факт утечки не установлен.
- **R04 / P2 / CODE REVIEW:** `scripts/app-server.ts:558` health проверяет наличие pool/config, а не живое соединение/доставку. Успешный production health не доказывает исправность БД и интеграций.
- **R05 / зависимости:** npm audit сообщил12 затронутых пакетов (8 high,4 moderate), но всего3 уникальных advisory. `image-size` находится в Metro/build tooling: вредоносный импортируемый asset может зависнуть; эксплуатация из мобильного runtime не доказана. `decode-uri-component` достижим по цепочке query-string → navigation; нужен ограниченный тест malformed deep link и обновление.
