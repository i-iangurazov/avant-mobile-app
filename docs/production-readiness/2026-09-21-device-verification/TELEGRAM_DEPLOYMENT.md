# Telegram: рабочие заказы и статусы

**Реальная доставка и callback подтверждены 21.09.2026.** После явного разрешения владельца новый backend опубликован в Railway, подключён к общей базе сайта и зарегистрировал HTTPS webhook. Старый Bazaar proxy больше не обслуживает приложение.

Тест **AV-20260921-01000** помечен «ТЕСТ — НЕ СОБИРАТЬ». Сервер отправил сообщение; владелец нажал «Подтверждён». В той же записи заказа сохранены `status=confirmed`, event source `telegram_admin`, `inventory_held=false`. Production Android после входа владельца показывает этот статус. Повтор запроса возвращает тот же order ID. Оплаты и резервирования не было. Тестовую заявку не исполнять; владелец может отменить её кнопкой в Telegram.

[Доказательство live](evidence/production-live-check.json), [Android](evidence/native-production-release.json), [44 изолированные HTTP/DB проверки](evidence/telegram-orders.json), [фактический rollout и rollback](RAILWAY_ROLLOUT.md).

После COMMIT заказа сервер будит долговечную очередь; ошибка Telegram не отменяет заказ. Worker ограничен организацией; callback проверяет secret, чат, права оператора, организацию и исходное message ID. Повтор callbacks не создаёт второй event. Ответ «message is not modified» считается успешным повтором. Health возвращает503 при неудачной регистрации webhook.

Локальные проверки включают 20 параллельных повторов заказа/callback, чужую организацию/chat/message, обычного участника, неверный secret/status и retry. Bot API не гарантирует exactly-once sendMessage при потере ответа после фактической доставки: повторное уведомление возможно, но второй заказ не создаётся.

Для staging использовать отдельного бота: один bot имеет один webhook. Read-only диагностика — `npm run check:telegram` с конфигурацией выбранной среды. Никогда не переназначать production webhook на локальный тест и не включать `drop_pending_updates` при обычном восстановлении.

Исторические evidence `telegram-live-readonly.json` и `telegram-backend-readonly.json` фиксируют состояние **до** внедрения. Они не описывают нынешний сервер. Сквозная production-проверка в этом запуске относится к заказу товара; ручное восстановление и остальные уведомления имеют отдельные критерии.
